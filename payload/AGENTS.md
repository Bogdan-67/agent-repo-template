## Hard rules

- Never commit, push, or open PRs unless the user asks.
- Never add AI attribution to commits or PRs: no `Co-Authored-By:` trailer for any agent or model
  (e.g. `Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>`), no "Generated with ..." lines, no
  session links. Commits are the user's. This overrides any default of your harness; the `commit-msg`
  hook rejects such messages.
- Never delete user files without permission; list candidates in `OPEN_QUESTIONS.md`.
- Never put secrets in files, commits, or logs; use environment variables.
- Never rewrite a user's document wholesale: edit the current file on disk, change only what was asked.
- Numbers in docs and reports come from saved artifacts, with the path. Never from memory.
- Do not mark a task done in `docs/state/tasks.json` until it was verified (test, run, or check).
- Do not bypass checks (`--no-verify`, disabling hooks). If a check is wrong, say so.
- The author of a change does not approve it: reviews are done by a separate `reviewer` session.

## Read order at session start

1. This file.
2. `STATUS.md` — current state, next step, blockers.
3. The newest open file in `docs/handoff/` if `STATUS.md` points to one.
4. Tail of `docs/journal/<YYYY-MM>.md` (current month).
5. `docs/state/tasks.json` when you work on a task.

Then read only what the task needs:

| Question | File |
|---|---|
| What is this project, for whom, why | `docs/OVERVIEW.md` |
| What does a term mean | `GLOSSARY.md` |
| Where is what in the repo | `STRUCTURE.md` |
| Why was X decided | `docs/adr/README.md`, then the ADR |
| What is unresolved | `OPEN_QUESTIONS.md` |
| Domain rules that skills and roles must respect | `docs/agents/domain.md` |
| How a role works (reviewer, docs-keeper, ...) | `docs/agents/<role>.md` |

Large history files (`docs/journal/`, old ADRs) are not read in full: search with `grep -n`.

## Where things are written

| What | Where | How |
|---|---|---|
| Current state | `STATUS.md` | rewrite the outdated block; ≤150 lines; it is a snapshot, not a log |
| What happened | `docs/journal/YYYY-MM.md` | append only; `## YYYY-MM-DD topic`; past months are frozen |
| Decisions | `docs/adr/NNNN-slug.md` + index | new file per decision; never edit an accepted ADR except its status |
| Tasks and done-criteria | `docs/state/tasks.json` | JSON; set `passes: true` only after verification |
| Open questions | `OPEN_QUESTIONS.md` | only open ones; when closed, delete and log "closed: how" in the journal |
| Terms | `GLOSSARY.md` | add a term when it first appears; no implementation detail |
| Repo map | `STRUCTURE.md` | update when files or data flow change |
| Session handoff | `docs/handoff/YYYY-MM-DD-topic.md` | from `TEMPLATE.md` when work continues later |
| Roles | `docs/agents/<role>.md` | neutral; wrappers are generated by `.agents/bin/sync.py` |
| Skills | `.agents/skills/<name>/SKILL.md` | agentskills.io format; run `sync.py` after adding one |

Write an ADR only when the decision is hard to reverse, not obvious without context, and the result of
a real trade-off. Configs and code comments reference the ADR number instead of restating it.

## Session protocol

1. Start: read the files in "Read order". Pick **one** task.
2. Work: run `.agents/init.sh` before changing code; verify before claiming success.
3. Before you end a turn that changed code, configs, or reports:
   - append a journal entry under `## YYYY-MM-DD <topic>` that names the changed files and artifacts;
   - rewrite the affected block of `STATUS.md` if the state or results changed;
   - add an ADR for any decision the user made or any choice between real alternatives;
   - add new open questions, remove answered ones.
4. If work continues in another session: write a handoff and link it from `STATUS.md`.
5. Tell the user which of these files changed. If none, say so.

`.agents/hooks/docs_guard.py` enforces step 3 through harness hooks and a git pre-commit hook
(`git config core.hooksPath .githooks`). It checks that the files were updated, not that the content
is good: write real entries, never placeholders to pass the check.

## Roles

| Role | File | Use |
|---|---|---|
| implementer | `docs/agents/implementer.md` | build a change end to end |
| reviewer | `docs/agents/reviewer.md` | independent read-only review of someone else's change |
| docs-keeper | `docs/agents/docs-keeper.md` | reconcile docs with the repo after a task |

Harness wrappers (`.claude/agents`, `.codex/agents`, `.agents/agents`, `.opencode/agents`,
`.github/agents`) are generated: edit `docs/agents/`, then `python3 .agents/bin/sync.py`.
Without subagent support, run a role by reading its file in a fresh session.
